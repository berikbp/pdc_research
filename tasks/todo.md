# План: гибридный CPU–GPU инференс, этап 1 (ноутбук Берика, Pop!_OS)

RQ1: при каких условиях CPU+GPU обгоняет GPU-only и сдвигает ли язык запроса эту границу.
RQ2: хватает ли для выбора конфигурации политики, знающей только длину последовательности.
Учитель направление одобрил (сообщено 15.11.2026).

- [x] cmake 4.4.5 и ninja через `uv tool install` (без sudo)
- [x] CUDA toolkit 13.0.88 в `vendor/cuda` (`configs/cuda-linux-13.0.txt`; драйвер 580 не тянет 13.1)
- [x] Сборка закреплённого llama.cpp (`ecdd29e`), сервер видит RTX 4060
- [x] Профили `configs/machines/berik-popos.json` и `berik-popos-smoke.json`, новый `machine_id`

- [x] Манифесты нагрузок (`prepare`)
- [x] Тесты проекта проходят на этой машине
- [x] Smoke: g0 и g99

## Шаг 2. Подробный sweep по слоям, 7B
- [x] Разобраться с `-ngl 0`: пилот показал, что `--device none` даёт 99,2 мс/токен против 97,1 при `-ngl 0` (все 28 блоков на CPU в обоих случаях); для 14B берём `--device none` как чистую базу CPU-only
- [x] Все `-ngl` от 0 до 29, 8 потоков (2400 запросов, `docs/results/layer-sweep-7b-v1/`)
- [x] Разбор логов сервера: размещение пишется в каждый результат; g28 оставляет на CPU один первый блок, выходной слой уходит на GPU первым
- [x] Модель стоимости: +2,46 мс/токен за блок на CPU, 1,40 мс пересылка, 7,34 мс выходной слой, R² = 0,9997
- [ ] Перебор потоков в конфигурациях с слоями на CPU (код Берика переиспользуется) — необязательно, не сделано

## Шаг 3. Модель, которая не влезает в 8 ГБ
- [x] Qwen2.5-14B Q4_K_M (около 9 ГБ): закрепить ревизию и хэши
- [x] Частичный offload против CPU-only: предел 41 слой из 49, в 3,1 раза быстрее CPU (`docs/results/layer-sweep-14b-v1/`)

## Шаг 4. Параллельные запросы EN и KK
- [x] `-np` 1, 4, 16 на 7B и 14B, четыре языка, два раунда (длина выхода осталась фиксированной, 64 токена)
- [x] Throughput и VRAM под KV-кэш: память выделяется при старте и от языка не зависит; на 14B казахский вытесняет с GPU до трёх слоёв и не выигрывает от 16 слотов (`docs/results/parallel-14b-v1/`)
